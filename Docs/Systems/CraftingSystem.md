# 제작 시스템

## 목적과 진입 흐름

제작 화면은 개인정비의 에이베리 보급소에서 `제작대`를 선택하면 열린다. `WBP_Store`는 제작 화면을 최초 진입 시 생성해 재사용하며, 보급소를 다시 열면 기능 선택 화면으로 초기화한다.

화면 레이아웃은 `WBP_Crafting`과 그 하위 WBP들이 소유하고, 목록 생성·필터·선택·제작 처리는 `Source/LostSignal/UI/Lobby/Crafting/`의 C++ 부모 클래스가 담당한다. 제작 가능 표시용 별 아이콘은 현재 범위에 포함하지 않는다.

## 데이터 소유권

- 레시피 Row 구조는 `Source/LostSignal/Data/LSCraftingRecipeRow.h`가 단일 출처다.
- 실제 결과물·재료·골드 비용·표시 순서는 `DT_CraftingRecipe`에서 기획자가 관리한다.
- 현재 테이블은 기획 확정본인 칩 제작 레시피 24종(`Craft_Chip_1`~`Craft_Chip_24`)을 담는다. 등급 6단계 × 칩 종류 4종(체력/적재/전투/탐색)이며, 재료는 문서의 재료 공유 규칙(체력=프레임 / 적재=코어 / 전투=구동계 / 탐색=프로세서 + 부품 상자 공통)을 따른다. 레시피 FName·정렬 순서는 기획 의도를 그대로 유지한다.
- 결과물과 재료의 이름·설명·아이콘·등급·스택 수는 기존 아이템 DataTable이 소유한다. 레시피 테이블에 복사하지 않는다.
- 제작 테이블 참조는 `ULSDropSettings.CraftingRecipeTable`에 매핑한다.
- 재료 슬롯은 레시피의 재료 배열 길이만큼 동적으로 생성하며 개수 제한을 두지 않는다. 칩처럼 인스턴스 스탯을 가진 아이템은 재료로 사용하지 않는다.

## 목록과 상세 표시

- 최초 진입 카테고리는 `ALL`이고, 현재 필터의 첫 레시피를 자동 선택한다.
- 필터는 결과물 RowName과 `Item_Type`으로 무기·방어구·칩·소모품을 판정한다.
- 목록 우측 보유량과 재료 보유량은 인벤토리와 창고를 합산하며 보호 슬롯은 제외한다.
- 행과 중앙 재료 아이콘은 기존 `WBP_ItemSlot`의 표시 전용 컨텍스트와 툴팁을 재사용한다.
- 제작 가능한 레시피 행은 비선택 상태에서 별도 테두리색으로 구분하며, 선택 중에는 기존 선택 테두리색을 우선한다.
- 제작 가능 수는 재료, 골드, 인벤토리/창고 결과물 공간을 모두 반영한다. 제작 버튼은 1개 이상 제작 가능할 때만 활성화되며 클릭당 결과물 1개를 만든다.

## 원자적 제작 규칙

제작 상태 변경은 `ULSSaveSubsystem::TryCraft` 한 경로에서 처리한다.

1. 인벤토리와 창고의 재료 및 골드를 다시 검증한다.
2. 인벤토리 재료를 먼저 차감하고 부족분을 창고에서 차감한다.
3. 재료 차감으로 생긴 공간까지 반영해 완성품을 인벤토리에 먼저 넣는다.
4. 인벤토리에 넣을 수 없으면 창고에 넣는다.
5. 두 곳 모두 수용할 수 없으면 재료와 골드를 포함한 모든 변경을 폐기한다.
6. 성공한 상태만 한 번 저장하고, 골드가 바뀌었으면 기존 골드 변경 알림을 발행한다.

칩 결과물은 실제 제작 성공 시 기존 `LSChipStats::RollChipStats`로 인스턴스 스탯을 한 번 생성한다.
